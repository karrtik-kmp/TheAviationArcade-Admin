|---|---|---|
| `catalog.v1.json` | `Backend/contracts/catalog.v1.json` (backend B2, `16351d0`) | Byte copy of the backend's committed file (LF). When the backend republishes it, copy it again with `git -C <Backend> show HEAD:contracts/catalog.v1.json > contracts/catalog.v1.json`. `tests/catalog.test.mjs` checks the website catalog against it. |
| `backend-progress.example.json` | Written for the website's tests | A sample `GET /v1/me/progress` response shaped by `Backend/docs/openapi.yaml` (0.4.0) `ProgressEnvelope`. The values are test data, not real progress. `tests/progress.test.mjs` checks it against the strict Progress schema. |
| `openapi.yaml` | `Backend/docs/openapi.yaml` (API 0.28.0, backend `a58a15f`, copied 2026-11-19) | Byte copy, never edited. Refresh with `git -C <Backend> show HEAD:docs/openapi.yaml > contracts/openapi.yaml` when the backend announces a bump. 0.27.0 made the module `identifier` (commercial Aircraft Identifier) listable on `GET /v1/admin/content/identifier/items`; 0.27.1 changes descriptions only (on a dev backend with the dev demo waiver a published `ImageRef` or Plane of the Day feature may carry `licenceName: null`), and the strict parsers already accept a null `licenceName`. 0.27.2 and 0.27.3 change `servers` only. 0.28.0: an admin grant also marks the account's Firebase email verified; its 200 is `AdminGrantEnvelope` (`emailVerification`), with new refusals 409 `account_email_mismatch` and `account_disabled`, 404 for no Firebase account, and 503 when Firebase or the backend's admin key is missing. The role schemas in `lib/request/roles.ts` follow it (`OwnRole`, `AdminRoleRow`, `AdminGrantEnvelope`, `RoleRequestList`, `PhotographerRequestResult`); `tests/roles.test.mjs` checks them against it. |
